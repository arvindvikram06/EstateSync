# Purpose of a visit

A site visit is a request to view a property at a proposed date and time. It is separate from saving a property and separate from applying to rent it. A visit does not reserve the property, approve the tenant, or create a lease. Application and visit activity can be tracked independently.

# Tenant request flow

Open an eligible property and choose Request a Visit. Select a specific future date and time supported by the form and submit the request. The request is sent to the property owner with Pending status. The requested time is a proposal until the owner approves it. Do not assume a visit is confirmed from submission alone.

Only one active visit request per tenant and property is allowed by the current workflow. If a request for the same property is still Pending or Approved, manage that request instead of creating another. A new request can be made after the previous one reaches a state that no longer counts as active, such as Cancelled, Declined, or Completed, subject to current property availability.

# Owner response

The owner receives a notification and can review the proposed date and time from the Owner dashboard’s visit area. A Pending request can be Approved or Declined. A decline can include a useful note. Once another status has been recorded, repeated approve or decline actions are not valid. The tenant receives the decision.

# Status meanings

Pending is waiting for the owner. Approved confirms the proposed visit. Declined means the owner did not accept it. Cancelled means the tenant withdrew the request. Completed means the visit has taken place and the workflow is finished. These statuses describe only the visit; they do not determine application or lease status.

# Cancellation

A tenant can cancel a Pending or Approved visit while cancellation is still allowed. Cancellation notifies the owner and frees the tenant to request another visit later. A Declined, Cancelled, or Completed visit cannot be cancelled again. If plans change close to an approved time, cancel through EstateSync so the owner sees the updated state.

# Date and time problems

Use the date and time displayed by the application and confirm them before submitting. Past dates and otherwise invalid scheduling values should be rejected. If the selected time becomes unavailable after submission, the owner can decline and the tenant can make a new request. EstateSync does not treat an owner’s silence as approval.

# Property availability changes

A property can become leased or otherwise unavailable while visit activity exists. An approved visit does not guarantee that the listing remains rentable. Check the property and visit statuses before traveling or applying. If a visit option disappears, the listing state or an existing active request may explain it.

# Safety and privacy

Use platform records and appropriate communication for visit coordination. Do not place identity-document numbers, payment credentials, passwords, door-access codes, or other sensitive information in visit notes. The assistant can explain statuses but cannot confirm physical attendance or override an owner’s response.
