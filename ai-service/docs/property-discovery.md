# Browsing available properties

The Properties page shows listings that are eligible for tenant discovery, such as approved active properties and any availability states intentionally exposed by the platform. Draft, rejected, pending-approval, or currently unavailable listings are not ordinary public results. Each card summarizes information such as image, location, bedroom count, property type, and monthly rent. Open a card to view the fuller description, amenities, area, deposit, and other published details.

# Searching and filtering

Use the location search and available filters to narrow results. Property type, minimum bedrooms, and rent boundaries can be combined. A bedroom selection represents the displayed filter behavior, including any “or more” interpretation shown by the interface. Minimum rent should not exceed maximum rent. Removing a filter broadens results again.

No results does not necessarily mean an error. The selected filters may be too restrictive, the location spelling may not match available listings, or matching properties may no longer be active. Clear filters one at a time and retry. Refresh a property detail before acting because availability can change after the search results were loaded.

# Property types and details

EstateSync displays only property types supported by the current listing form. Published details originate from owner input that passed the listing workflow, but tenants should still review the complete listing and visit the property before making a rental decision. Optional map pins help assess approximate or provided location context; the absence of a pin does not necessarily make a listing invalid.

# Saving and unsaving

Saving creates a private shortcut in the tenant dashboard. It does not reserve the property, notify the owner, create an application, or guarantee that the property will remain available. A saved property can be removed with Unsave. If a saved listing later becomes leased or unavailable, it may stop appearing in normal browse results even though historical saved activity existed.

# Viewing a property versus applying

Opening a property page is informational. Requesting a site visit schedules a proposed viewing with the owner. Applying formally asks to rent the property and requires the relevant eligibility checks. These actions are separate and can have different statuses. A tenant may decide to apply without a visit or request a visit before applying, subject to the current interface and property availability.

# Availability changes

A property can move from Active to Leased when a lease becomes active. Near the end of a lease, it may be marked Available Soon according to the platform lifecycle. Availability shown in a previous browser tab can become stale when another workflow changes the property. If Apply or Request Visit becomes unavailable, reopen or refresh the listing and check its current status.

# Privacy of published information

Public property pages display listing information and property photos intended for prospective tenants. Ownership-verification documents, private identity documents, payment details, and internal review notes are not public listing content. Users should not ask the assistant to reveal private owner or applicant records.

# Common discovery problems

If a known listing cannot be found, it may be pending approval, rejected, leased, inactive, or filtered out. If a detail page no longer permits an action, the status may have changed. Saving should not be treated as a hold. Before applying, confirm KYC approval; before relying on a visit, confirm the visit request status and scheduled time in the dashboard.
