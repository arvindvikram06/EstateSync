## 2. Property Images Not Displaying

**Symptom:** Images uploaded to properties were broken (showed placeholder/error) in both the edit and create pages.

**Root cause:** The image URLs returned by the backend are relative paths (e.g. `/uploads/properties/...`). The template was binding directly: `[src]="img.image"`, which resolves relative to the frontend origin (`localhost:4200`), not the API (`localhost:5000`).

**Fix:**
- Added `imageUrl(path: string): string` helper to `PropertyService` that prepends `environment.apiUrl` when the path is relative.
- Changed all image `src` bindings to use `propSvc.imageUrl(img.image)`.
- Changed `propSvc` from `private` to `public readonly` in both components so the template can call it.

**Files:**
- `core/services/property.service.ts` — added `imageUrl()` helper
- `features/properties/property-create/property-create.component.ts` — `propSvc` made public
- `features/properties/property-create/property-create.component.html` — `[src]="propSvc.imageUrl(img.image)"`
- `features/properties/property-edit/property-edit.component.ts` — `propSvc` made public
- `features/properties/property-edit/property-edit.component.html` — `[src]="propSvc.imageUrl(img.image)"`

## 3. Infinite GET /api/v1/kyc/me Loop

**Symptom:** Clicking "Complete Verification" in the dashboard triggered an infinite loop of `GET /api/v1/kyc/me` requests, flooding the network tab.

**Root cause:** A cycle between `IdentityWizardComponent.ngOnInit()` and the `KycStore.loadExisting` rxMethod:

1. `IdentityWizardComponent` mounts → `ngOnInit` calls `store.loadExisting()`
2. `loadExisting` sets `step: 'loading'`
3. The dashboard template has `@if (step !== 'loading')` to render the wizard → component is destroyed
4. The HTTP response arrives → `step` is set to `'intro'` (or whatever state)
5. The `@if` condition becomes true → `IdentityWizardComponent` is recreated
6. `ngOnInit` fires again → `store.loadExisting()` → repeat from step 1

**Fix:** Removed `ngOnInit` from `IdentityWizardComponent` entirely. The `KycStore` is `providedIn: 'root'` (singleton) and is already loaded before the wizard mounts — it does not need to re-fetch on every mount.

**Files:** `features/kyc/components/identity-wizard/identity-wizard.component.ts`

## 4. KYC Dashboard State Stale After Submission (No Refresh)

**Symptom:** After completing KYC submission, navigating back to the dashboard still showed "Complete Verifications" banner. The status only updated after a full page refresh.

**Root cause:** The `submitKyc` rxMethod in `KycStore` only patched `step: 'done'` on success, but left `kyc().status` as `'Draft'`. The dashboard's overview tab reads `store.kyc()?.status` to decide which banner to show. Because the singleton store held stale `status: 'Draft'`, the "Under Review" banner never appeared.

The dashboard's `ngOnInit` also had a guard: `if (step === 'loading') { reload }` — since step was `'done'` (not `'loading'`), it skipped the API re-fetch entirely, so the stale state persisted until page reload.

**Fix:** In `submitKyc`, after the success `tap`, also patch the `kyc` object's `status` field to `'Pending'`:

```typescript
tap(() => patchState(store, {
  isSubmitting: false,
  step: 'done',
  kyc: store.kyc() ? { ...store.kyc()!, status: 'Pending' } : null,
})),
```

**Files:** `core/stores/kyc.store.ts`

## 5. Financial Profile Dashboard State Stale After Submission

**Symptom:** Same pattern as fix #4 — submitting the financial verification wizard left the dashboard banner showing "Not Submitted" instead of "Under Review" until a page refresh.


## 7. Property Edit — Map Never Showing

**Symptom:** The Leaflet map on the property edit page was blank/never initialized.

**Root cause:** The `#mapEl` div is inside an `@else if (property())` block. When `ngAfterViewInit()` fires, `property()` is still `null` (data hasn't loaded yet), so the div is not in the DOM — `@ViewChild('mapEl')` returns `undefined`, and Leaflet never initializes.

**Fix:**
- Removed `implements AfterViewInit` and the `ngAfterViewInit` method.
- Added an `effect()` in the constructor that watches `loading()` and `property()`:

```typescript
constructor() {
  effect(() => {
    if (!this.loading() && this.property()) {
      queueMicrotask(() => this.initMap());
    }
  });
}
```

`queueMicrotask` defers map initialization until after Angular has painted the DOM for the current signal change, ensuring `#mapEl` is present before Leaflet tries to mount.

**Files:** `features/properties/property-edit/property-edit.component.ts`

## 9. Property Amenity Key Mismatch

**Symptom:** Amenities were not saving or loading correctly between frontend display names and backend normalized keys.

**Root cause:** Backend stores amenity names normalized (lowercase, no spaces: `swimmingpool`, `powerbackup`). Frontend display names are `'Swimming Pool'`, `'Power Backup'`. Direct string comparison failed.

**Fix:**
- Added `normalize = (s: string) => s.toLowerCase().replace(/\s+/g, '')` utility.
- `isSelected(name)`: checks if any selected amenity normalizes to the same key.
- `toggleAmenity(name)`: stores display names in the set, uses normalized key for dedup.
- On load: maps backend keys back to display names using `AMENITY_LIST.filter(name => loadedKeys.has(normalize(name)))`.
- Fixed `updateAmenities` request body key from `{ amenities }` → `{ amenityNames }` to match backend.

**Files:** `core/services/property.service.ts`, `features/properties/property-create/property-create.component.ts`, `features/properties/property-edit/property-edit.component.ts`
